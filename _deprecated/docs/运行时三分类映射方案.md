# 运行时三分类映射方案（PyTorch Dataset 在线转换）

> **状态**：方案设计 · 未实施
> **核心思路**：不在磁盘上生成 `train_masks_class/`，三分类标签在 `Dataset.__getitem__` 中由原始二值 mask 实时计算
> **适用前提**：主分割任务仍是**二分类**（前景/背景），三分类标签用于采样权重、辅助分类头、评测分层——**不是主 loss 的 target**

---

## 1. 为什么考虑运行时映射

上一轮的方案是**磁盘预处理**：跑一次 `relabel_masks.py` 生成 `train_masks_class/`（24MB 彩色 PNG），训练时直接读。优点是离线、可复现、肉眼可看；缺点是：

| 缺点 | 影响 |
|---|---|
| 阈值（20%/15%/3/64px）一旦改，要重跑一次 | 调参时反复生成文件，烦 |
| 多一份磁盘副本（24MB × 5 折 × 实验版本） | 小项目能扛，大项目啰嗦 |
| 单一数据源被打破 | 训练读 `train_masks_class`、推理读 `train_masks`，两套路径 |
| 产物是"图片"不是"标签" | 彩色 PNG 给人看方便，给程序读要再解码 |

**运行时映射**把三分类作为 Dataset 的派生字段，原始数据源始终只有 `train_masks/`（0/255 二值），三分类标签是计算结果而非存储结果。这样：

- 调参只改 Dataset 的 `__init__` 参数（阈值、规则），不碰磁盘
- 数据源单一：训练/推理/评测都读 `train_masks/`
- 彩色 PNG 仍是可选的可视化产物，但不是训练依赖

---

## 2. 三种实现路径对比

### 路径 A：纯运行时计算（每个 epoch 重算）

每次 `__getitem__` 读原始 mask → `scipy.ndimage.label` → 规则C → 返回标签。

```
读 mask (PNG) → 二值化 → 填空洞 → label → 剔噪点 → 算指标 → classify → 标签
```

| 维度 | 评价 |
|---|---|
| 磁盘 | 0 额外占用 |
| 实现复杂度 | 低（一个函数） |
| 性能 | **差**：scipy `label` 对 1024×1024 mask 约 30-50ms/张，4953 张 × N epoch 重复计算 |
| 适用场景 | 调参期、小数据集、验证想法 |

**结论**：适合临时验证，不适合长期训练。

### 路径 B：预计算标签索引（推荐）

启动时扫一遍 `train_masks/` 算出每张 patch 的三分类标签（+ 连通域指标），缓存为一个小文件（`.npy` 或 `.parquet`，几百 KB）。`__getitem__` 只查表，不重算。

```
启动一次 → 扫 4953 张 → 算标签 → 存 patch_labels.npy (4953 个 int8) → __getitem__ 查表
```

| 维度 | 评价 |
|---|---|
| 磁盘 | ~5KB（int8 × 4953）+ 可选指标表 ~500KB |
| 实现复杂度 | 中（一个 build_label_index.py + Dataset 查表） |
| 性能 | **优**：__getitem__ 只多一次 numpy 索引，O(1) |
| 调参灵活性 | 改阈值 → 重跑 build（约 1 分钟） |
| 适用场景 | 长期训练、多折交叉验证、论文实验 |

**结论**：推荐。本质是"把磁盘预处理产物从 24MB 彩色 PNG 换成 5KB 的标签索引"，既保留"不污染数据源"的初衷，又避免每 epoch 重算。

### 路径 C：混合（A + B 兜底）

预计算索引，但 Dataset 保留 `compute_on_the_fly` 参数，调试时可切到路径 A 验证一致性。

**结论**：默认用 B，加一个 `--recompute` 开关兜底，最适合长期项目。

```python
class ToxPathDataset(torch.utils.data.Dataset):
    """WSI patch 数据集，主任务是二分类分割，三分类标签用于辅助。

    数据源（只读）:
        - train_patches/{slide}/1.0/{X}_{Y}.jpeg   # H&E 1024×1024
        - train_masks/{slide}/1.0/{X}_{Y}.png      # 二值 mask 0/255

    派生:
        - patch_label: int (1/2/3)，来自 _patch_labels.npy 查表
    """

    def __init__(
        self,
        data_root: Path,
        slides: list[str],              # ["train_001", "train_003"]  # 留一折
        image_size: int = 224,          # 训练随机裁 224（14 倍数）
        label_index_path: Path | None = None,  # _patch_labels.npy
        label_cfg: RelabelConfig | None = None,  # recompute 模式用
        augment: bool = True,
        mode: Literal["train", "val"] = "train",
    ) -> None:
        # 1) 枚举 patches，建立 (slide, name) → 路径 索引
        # 2) 加载三分类标签索引（或 recompute）
        # 3) 预计算 WeightedRandomSampler 的 sample_weight
        ...

    def __len__(self) -> int:
        return len(self.samples)

    def __getitem__(self, idx: int) -> dict[str, Tensor]:
        """返回:
            image:   [3, image_size, image_size] float32
            mask:    [1, image_size, image_size] long (0/1)   # 主任务 target
            label:   scalar long (1/2/3)                      # 辅助任务 target
            sample_weight: scalar float                       # 采样权重
        """
        # 1) 读 patch + mask（PIL）
        # 2) 同步随机裁 224（patch 和 mask 用同一裁剪框）
        # 3) 增强（翻转/90°/HED 颜色抖动）
        # 4) Bioptimus 归一化
        # 5) label = self.labels[idx]  # 查表 O(1)
        # 6) sample_weight = self.sample_weights[idx]
        ...

    def get_sample_weights(self) -> np.ndarray:
        """供 WeightedRandomSampler 用。

        权重设计（基于三分类）:
            标签1 (纯背景): 1.0
            标签2 (零星/小灶/中等): 4.0   # 最稀缺且最难学，加权最高
            标签3 (大块): 2.0            # 数量较多且易学

        可在 __init__ 用 class_balance 参数覆盖。
        """
        ...
```

### 3.4 与现有模型/loss 的对接

```
Dataset → batch {image, mask(0/1), label(1/2/3), sample_weight}
                ↓
           WeightedRandomSampler (用 sample_weight)
                ↓
           DataLoader
                ↓
           ToxPathSegmentor(image) → seg_logits [B,2,H,W]
                ↓
           DiceCrossEntropyLoss(seg_logits, mask)   # 主任务，二分类
                ↓
           (可选) AuxClassificationHead(features) → cls_logits [B,3]
                ↓
           (可选) CrossEntropyLoss(cls_logits, label)  # 辅助任务，三分类
```

关键点：
- **主 loss 永远是二分类**：mask 是 0/1，`DiceCrossEntropyLoss` 的 `num_classes=2`
- **三分类标签不打进 mask**：mask 仍是原始二值，不污染主任务监督信号
- **三分类的两个用途**：① 采样权重（必选）② 辅助分类头（可选，多任务正则化）
- 若不加辅助头，三分类标签只影响采样，模型本身完全不知道有"三类"——这是最干净的设计

## 4. 性能考量

| 操作 | 耗时 | 频率 |
|---|---|---|
| 启动时 build_index（扫 4953 张） | ~50s | 一次 |
| Dataset.__init__ 加载 .npy | <10ms | 每 epoch |
| __getitem__ 查表 | <1μs | 每 sample |
| __getitem__ 读 JPEG+PNG+裁剪+增强 | ~5-15ms | 每 sample |

对比路径 A（纯运行时）：__getitem__ 多 30-50ms/张，4953 张/epoch 多 2-4 分钟/epoch，100 epoch 多 3-7 小时——**显著慢**，所以推荐 B。

## 5. 与 train_masks_class 的取舍

`train_masks_class/`（上一轮生成的 24MB 彩色 PNG）的去留：

| 选项 | 评价 |
|---|---|
| **保留作可视化** | ✅ 给人看方便、给论文截图方便，但训练不读它 |
| **删除** | ✅ 减少混淆（避免有人误以为训练读彩色 PNG） |
| **改名为 _visualization_only** | ✅ 语义清晰，明确"仅供可视化" |

建议：保留 `train_masks_class/` 作为可视化产物，但在 `README.md` 和方案文档里**明确标注"训练不读此目录，三分类标签来自 `train_masks/` + 运行时映射"**。

## 6. 优点与局限

### 优点

1. **数据源单一**：训练/推理/评测都只读 `train_masks/`，没有"训练读 A 推理读 B"的双路径问题
2. **调参不碰磁盘**：阈值改了重跑 `build_label_index.py`（1 分钟），不重新生成 24MB PNG
3. **小文件**：5KB 索引 vs 24MB PNG，git 友好
4. **可复现**：`RelabelConfig` 序列化进索引文件元数据，扫一眼就知道用的什么阈值
5. **主任务干净**：mask 始终是 0/1 二值，三分类只影响采样与辅助头，不污染主 loss

### 局限

1. **可视化要手动**：想看彩色图得另跑脚本（但已有 `relabel_masks.py` 可复用其 colorize 逻辑）
2. **首次启动慢 50 秒**：build_index 一次，可加 `--cache` 跳过
3. **依赖 scipy**：Dataset 启动时需要 scipy.ndimage（已在 toxpath 环境装好）
4. **索引与数据需对齐**：如果 `train_masks/` 被增删 patch，索引会错位——加 `--verify` 校验文件名一一对应
